# 공지 게시글 수정 권한 검증 누락

일반 사용자가 쓴 글을 관리자가 공지로 지정한 뒤에도 원 작성자가 글을 수정할 수 있었다. 공지 상태를 유지하는 요청은 거부됐지만, 카테고리를 `자유`로 바꾸는 요청은 허용됐고 제목과 본문도 함께 변경됐다.

## 재현 조건

일반 사용자가 작성한 글을 관리자가 공지로 변경한 상태가 필요하다. 재현 요청은 그 글의 원 작성자 세션으로 보낸다.

판정의 기준은 “기존 공지 글은 관리자만 수정할 수 있다”는 정책이다. 실제 화면에서도 [public/app.js 195행](https://github.com/dev-code10/vibekill/blob/9fda842dda38a933034159e539ea7544c67615ac/moru-community/public/app.js#L195)에 따라 일반 사용자가 공지 글의 편집 창을 열지 못한다.

## 검증 과정과 결과

일반 계정으로 자유 게시글을 만든 뒤 관리자가 `PATCH /api/posts/1`로 카테고리를 공지로 변경했다. 조회 결과 카테고리는 `공지`, 작성자는 원래 일반 계정으로 유지됐다.

이 상태에서 아래 순서로 수정 요청을 보냈다. 제목과 본문은 같게 두고 요청 계정 또는 카테고리만 바꿨다.

| 요청 계정 | 요청한 카테고리 | 실제 응답 |
| --- | --- | --- |
| 다른 일반 사용자 | 자유 | `403`, 수정 권한 없음 |
| 원 작성자 | 공지 | `403`, 관리자만 공지 작성 가능 |
| 원 작성자 | 자유 | `200`, 수정 성공 |

거부된 두 요청 이후 글을 조회해 기존 본문과 공지 상태가 유지됐는지도 확인했다. 마지막으로 성공한 요청은 다음과 같다. 쿠키는 원 작성자의 세션을 사용했다.

```http
PATCH /api/posts/1
Content-Type: application/json

{
  "title": "작성자가 변경한 제목",
  "content": "일반 작성자의 요청으로 본문이 변경되었습니다.",
  "category": "자유"
}
```

서버는 `200`과 `{"ok": true}`를 반환했다. 이어서 `GET /api/posts/1`로 저장된 글을 조회했다.

| 값 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 카테고리 | 공지 | 자유 |
| 제목 | 공지 권한 검증용 게시글 | 작성자가 변경한 제목 |
| 본문 | 관리자가 공지로 지정하기 전의 본문입니다. | 일반 작성자의 요청으로 본문이 변경되었습니다. |
| 작성자 역할 | user | user |

성공 응답뿐 아니라 실제 데이터 변경까지 확인했다. 게시글 번호 `1`은 첨부 실행 기록의 값이다. [요청과 응답 기록](evidence/2026-10-13/notice-authorization.json) · [검증 코드](poc/notice-authorization.mjs)

## 원인

게시글 수정 경로는 [server.js 453행](https://github.com/dev-code10/vibekill/blob/9fda842dda38a933034159e539ea7544c67615ac/moru-community/server.js#L453)에서 기존 글의 작성자만 읽는다.

```sql
SELECT user_id FROM posts WHERE id = ?
```

[459행](https://github.com/dev-code10/vibekill/blob/9fda842dda38a933034159e539ea7544c67615ac/moru-community/server.js#L459)은 요청자가 작성자 또는 관리자인지 검사한다. 원 작성자는 이 검사를 통과한다. 그다음 공지 권한 검사는 DB에 저장된 카테고리가 아니라 요청의 새 카테고리를 사용한다.

```javascript
if (input.category === '공지' && req.user.role !== 'admin')
```

기존 글이 공지여도 `input.category`를 `자유`로 보내면 이 조건에 걸리지 않는다. 화면에서 편집 창을 막는 검사와 서버가 적용하는 권한 기준이 서로 다르다.

## 영향

원 작성자가 관리자의 공지 지정을 해제하면서 제목과 본문을 바꿀 수 있다. 관리자만 공지를 관리한다는 정책 아래에서는 공지의 내용과 분류를 보호하지 못하는 결과다.

다른 사용자의 글을 임의로 수정한 것은 아니다. 다른 일반 사용자의 요청은 작성자 검사에서 `403`으로 차단됐다. 공지 상태를 유지한 채 원 작성자가 내용을 수정하는 요청도 거부됐다. 작성자에게 공지 해제를 허용하려는 정책이라면 그 권한을 화면과 서버에 일관되게 반영해야 한다.

## 수정 방향

기존 글의 `category`를 함께 조회하고, 관리자 이외의 요청에서는 변경 전과 변경 후 카테고리를 모두 확인한다. 기존 작성자 검사도 유지해야 한다.

```javascript
// 기존 글에서 user_id와 category를 조회한 뒤 수행할 검사
if (req.user.role !== 'admin' &&
    (post.category === '공지' || input.category === '공지')) {
  return res.status(403).json({
    error: '공지 게시글은 관리자만 수정할 수 있습니다.',
  });
}
```

검사와 저장 사이에 다른 요청이 카테고리를 바꿀 수 있으므로 실제 적용 시에는 트랜잭션과 행 잠금, 또는 권한 조건을 포함한 원자적 갱신이 필요하다. 화면에서 편집을 막더라도 서버의 모든 수정 요청에서 권한을 검사해야 한다. [OWASP의 요청별 권한 검증 원칙](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html#validate-the-permissions-on-every-request)과도 같은 방향이다.

수정 후에는 원 작성자의 `공지 → 자유` 요청도 거부되고 기존 글이 그대로 남아야 한다. 관리자의 공지 수정과 일반 사용자의 자기 일반 글 수정은 계속 허용돼야 한다.
